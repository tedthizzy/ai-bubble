The clearest identified network exposure is Starlette's form parser in Streamlit. Streamlit 1.58.0's upload route calls `request.form()` after checking XSRF and an active session. Starlette 1.2.1 ignores field-count and field-size limits for URL-encoded forms. Small synthetic requests reproduced both failures; 1.3.1 rejected them. The route also checks Content-Length against Streamlit's upload size limit when that header is present. A full dashboard exploit was not attempted. See the preserved wheel excerpt in the inventory and the local launch command at [justfile:190](../justfile#L190).

GitPython accounts for 23 alerts, including GitHub's critical alert. A harmless config rewrite reproduced directive injection in 3.1.50; 3.1.62 prevented it. Code execution would require additional exploit steps. The inspected Streamlit utility opens the local repository and reads its metadata, but I found no configuration writer or attacker-controlled clone interface in the application or that utility. The [maintainer rates this alert high](https://github.com/gitpython-developers/GitPython/security/advisories/GHSA-284h-m62q-gf8w), while GitHub's database rates it critical. Both ratings are retained.

PyPI exposed three further GitPython advisories absent from the 54 repository alerts. Two match installed 3.1.50 under the maintainers' ranges: [repository metadata confusion](https://github.com/gitpython-developers/GitPython/security/advisories/GHSA-239g-whfq-7xj9) and [commit metadata parsing denial of service](https://github.com/gitpython-developers/GitPython/security/advisories/GHSA-g5vv-9gxw-82hx). A [third advisory](https://github.com/gitpython-developers/GitPython/security/advisories/GHSA-whh4-5q6c-9v3x) is associated with 3.1.50 by PyPI, but its maintainer specifies only 3.1.59. It is recorded as an upgrade concern, without counting it as another confirmed installed-version match. The proposed GitPython 3.1.62 is outside all three ranges.

Accelerate has no verified fixed release in this audit. The [advisory](https://github.com/advisories/GHSA-4j2p-28q2-5m79) lists affected versions through 1.14.0 and no patched version. PyPI lists no vulnerabilities for 1.15.0, but its published wheel still joins checkpoint `weight_map` values to a directory without checking containment, then passes the resulting paths into `load_state_dict`. Paths can escape the checkpoint directory. Special-file handling also remains unresolved. The proposed [upstream fix](https://github.com/huggingface/accelerate/pull/4138) was closed without merging. The remaining packages have these exposure conditions and proposed versions:

- setuptools: 1 alert; 81.0.0 to 83.0.0. Concerns excluded files leaking into source archives on normalization-sensitive filesystems. Bubble declares [Hatchling as its build backend](../pyproject.toml#L78).
- Torch: 1 alert; 2.12.0 to 2.13.0, paired with torchvision 0.28.0. Requires the affected TorchScript path. No matching calls were found in application or inspected Docling sources.
- Transformers: 1 alert; 5.9.0 to 5.10.1. Requires a malicious chat-template name followed by tokenizer or processor export. Docling loads models and processors; no `save_pretrained` call was found in the inspected callers. The advisory's minimum 5.10.0 is yanked, so the candidate uses non-yanked 5.10.1.
